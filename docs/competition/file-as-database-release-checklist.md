## 代码修复与验证（2026-10-27）

已修改功能代码，并增加对应回归测试：

- 默认全量推断，拒绝非 -1 的采样值；覆盖第 2049 行才出现字段、NULL 或不同类型的情况。
- CSV 溢出整数保留文本；JSONL 超出 i64 范围的整数、重复/空字段和有歧义字段报错。JSONL 全局列序固定，CSV 列名判重忽略 ASCII 大小写。
- 日期时间使用严格格式和微秒上限，保留声明的小数秒精度，C++ 转换使用列精度。
- CSV 在读取原始字节时按逻辑记录限制大小，修复预读缓冲区绕过上限的问题；JSONL 对 CRLF 和末行长度采用一致口径。解析错误包含文件和记录/行号。
- Unix 读取通过目录句柄逐级打开，禁止跟随校验后引入的符号链接，并避免 FIFO 打开阻塞。COPY 临时文件的创建、发布及清理也锚定到目录句柄，目标存在时不会覆盖。
- 文件身份在读取 CSV 表头或 Parquet Footer 前记录，在推断后及读取 EOF 后也检查变化。
- SQL 绑定拒绝重复参数、别名参数重复和格式不适用的参数。
- 空 glob 保留非 NULL 的 VARCHAR 列结构，只有表头的 CSV 返回可空 NULL 列。

验证入口：Rust 单测从原有 7 个扩展到 16 个，全部通过；`cargo clippy --all-targets -- -D warnings` 通过；本地 CMake 联合构建通过。SQL 集成测试在独立临时实例中运行，覆盖全量推断、LEFT JOIN、跨格式 JOIN、精度、参数、glob 及 COPY 失败清理。测试实例正常退出并清理数据。

以上为首轮状态。后续系统核对及新增修复、覆盖范围和资源边界见 [`file-sql-audit.md`](file-sql-audit.md)：已补计划缓存、Parquet 损坏输入、组合与资源校验、取消和 SQL 对照矩阵；非 Unix 文件入口现明确拒绝访问。大赛规模下的完整总回归仍须按正式评测配置运行。
